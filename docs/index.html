constitution

The self-managing software constitution — build it, ground it, maintain it, query it.

v1.0 Apache-2.0 inspired by software/constitution™

Why

Software projects accumulate rules — design invariants, security constraints, testing discipline — that live in tribal knowledge and decay. software/constitution™ made those rules machine-checkable at CI time. This project goes further: the constitution is built from evidence, maintained by detection, and queried by symptom — across the full software lifecycle.

The three self-management lanes

🟢 Derived

The registry is a build artifact. Regenerated from rule files on every push. Humans never hand-edit it.

🟡 Detect & Advise

Health checks find size-law crossings, drift, orphans. The agent advises you with evidence — never a drafted diff.

🔴 Human-Decided

Rule changes, splits, structural evolution. You ask; the skill drafts with alternatives; you ratify.

Quick start

# Linux/Mac
git clone https://github.com/phanijapps/constitution
cd constitution
./install.sh

# Windows PowerShell
.\install.ps1

The installer asks you to pick your coding agent and copies the skill to the right place.

What you get

📋 scaffold

Greenfield (interview) or brownfield (mine code+docs) — builds the 8-pack structure with charters, knowledge, and DRAFT rules.

🔍 query

Search rules, knowledge, and runbooks by symptom or concept. Returns progressive-loading-sized results with prerequisites.

🩺 health

Detects size-law crossings, orphan fragments, uncatalogued rules, undeclared modules. Advisory findings with evidence.

⚙️ derive

Regenerates the catalogue from rule files. The registry is a build artifact — never hand-edited.

📖 runbooks

Versioned procedural documents for incident response. Scar-born, post-incident checklist enforced.

🏗️ modules

Monorepo sub-constitutions per service or independently-published package.
