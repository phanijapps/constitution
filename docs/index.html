Constitutions your agents
can build and maintain.

A software constitution is your codebase's law — rules with evidence, counterexamples, and gates. This project provides the skill that builds it from code or interviews, the tooling that keeps it honest, and the query that finds root cause from symptoms.

Get started Read the spec

Why this exists

Projects accumulate rules that live in tribal knowledge and decay. software/constitution™ made them machine-checkable at CI time. This goes further: the constitution is built from evidence by an agent that interviews you or mines your code, maintained by detection that surfaces findings before they become incidents, and queried by symptom so root cause takes one search instead of a codebase read.

The three self-management lanes

Derived auto

The rule catalogue is a build artifact — regenerated from rule files on every push. Humans never hand-edit it.

Detect & Advise surface

Health checks find size-law crossings, drift, orphans. The agent advises you with evidence — never a drafted diff.

Human-Decided ratify

Rule changes, splits, structural evolution. You ask; the skill drafts with alternatives; you ratify.

What you get

scaffold

Build a constitution

# greenfield: interview
python3 scripts/scaffold.py --repo . --mode greenfield

# brownfield: mine code+docs
python3 scripts/scaffold.py --repo . --mode brownfield --docs docs/ README.md

# monorepo module
python3 scripts/scaffold.py --repo . --mode brownfield --module payments

query

Find the root cause

# by symptom
python3 scripts/query.py . "storage isolation project"

# by concept
python3 scripts/query.py . "recall degraded lane" --type knowledge

# by rule ID
python3 scripts/query.py . "PLT-002" --type rules

health

Detect before it breaks

# size law + orphans + drift + uncatalogued
python3 scripts/health.py .

# advisory in CI, blocking on --strict
# catalogue drift = CI failure (derived gate)

derive

Registry as build artifact

# regenerate catalogue from rule files
python3 scripts/derive_catalogue.py . --write

# prove committed = derived (CI gate)
python3 scripts/derive_catalogue.py .
Grounding

This project is the reference implementation of its own spec — the skill builds constitutions, the constitution governs the skill's own repository. The engram project is the original dogfood implementation.

Honest limitations

Structural-change authorization (L3 ratification) is designed but not yet implemented — it is an honour-system contract until the verification gate ships. The upstream software/constitution™ six-rule-class conformance is NOT implied by this spec.
